# State management #146: write evidence table

Draft survey for epic #146, on the operator's ruling of 2026-10-31 that narrows #146 to
two questions for each state write: (1) can the write be made atomically to the in-RAM
store (the embedded SQLite in `weaver-state`), and (2) is the write recorded correctly in
the trace. The loop (review judging, next_ready, placement, classifier, cuts, open
evidence, residency, selection) is out of scope and is not surveyed here.

Surveyed tree: `main` at `ea5d27e9`. Every test named below was opened and exists on this
tree, except the FL1 pins marked "in #427", which are in draft pull request #427 and not on
`main`. Tests marked "ignored" carry `#[ignore = "actual root coordination peer"]` or a
root-only scenario and do not run in the default suite. The 29 `root_plan_` tests among them
were run on 2026-10-31 for gap 1 (see its row); the others were not run.

## Reading the table

Path prefixes:

- `S/` is `crates/weaver-state/src/engine/serving_sqlite/`
- `M/` is `crates/weaver-state/src/member/`
- `H/` is `crates/weaver-harness/src/flow/`
- `T/` is `crates/weaver-trace/src/serving/`

"Atomic" evidence is a test that shows all-or-nothing: a refused or faulted write leaves
no partial row (the test compares the rows or the serialized image before and after), or
a transaction rolls back. A refusal that the code makes before the transaction opens is
noted as such, because it does not test rollback. "Trace" evidence is a test that asserts
the record the harness authors for the write (kind and payload). The harness records a
filing as `state.flow` phases plus a `state.store.measurement` whose `request_source`
names the filed source; plan effects are `plan.event`, `plan.break` or `step.outcome`;
marks are `state.mark`; pairs are `tool.call.started` and `tool.call.completed`; save
points are `save_point`.

Perturbations P1 to P8 are the ones run for this survey (section "Perturbations run").
"On record" means a perturbation written in `docs/project/` or in a test comment. The
records found for the harness (filing receipts, input, output, capture, pair accounting)
give counts of probes, not the test names, and each says it is not a SQLite commit test.
No perturbation on record names a store atomicity test in `S/`.
